Collection Analytics Suite

A multi-page web platform that reads a debt-collection CRM live and turns claims, call notes and payments into a daily plan for every collector — used every day by a collection team working two bank portfolios.

The problem

The team managed thousands of delinquent accounts across two banks, each with its own rules for what counts as “treated”. Every report lived in a separate Excel file, rebuilt by hand from CRM exports — so supervisors saw yesterday’s picture, and collectors didn’t know where to start their day.

What I built

One web app, connected read-only to the CRM, with 30+ report pages: live insights, a ranked call list, a per-collector day plan, promise tracking, neglect, distribution and rotation tools, bank-file analytics — each exportable to a formatted Excel file.

How it works

1 · PullClaims, follow-ups and payments from Odoo over JSON-RPC (or an uploaded export).
2 · UnderstandArabic call notes classified by an SVM model; bank rules applied per portfolio.
3 · DecideScores, roll-risk, best time to call, broken promises, salary-day timing.
4 · ActDay plan per collector, WhatsApp-ready messages, Excel reports for supervisors.

Highlights

  • Roll-risk radar — accounts that will move to a worse delinquency bucket within 7 days, with the money at stake.
  • Best time to call — answer rate per customer and per team by weekday × time slot, with shrinkage so tiny samples don’t win.
  • Collector day plan — today’s promises + at-risk accounts + top priorities, ordered by each customer’s best slot.
  • Unreachable customers — searches past follow-ups for a working number, otherwise prepares the official lookup list.
  • Bank-file analytics — money already sitting in the customer’s account, salary landed but installment not deducted, deferral & reschedule offers.

Engineering

  • Two portfolios, one codebase — a portfolio switch changes columns, rules and pages across the whole app.
  • Role-based access — admins choose which pages and portfolios each user sees; every action goes to an audit log.
  • Safe by design — CRM access is read-only, credentials live only in secrets, no customer data in the repo.
  • Tested — 120+ pytest tests on every pull request, plus Playwright end-to-end checks of the real UI.
  • Public demo — an in-process fake Odoo serves synthetic data through the same RPC interface, and a display filter swaps real names for generic ones.
